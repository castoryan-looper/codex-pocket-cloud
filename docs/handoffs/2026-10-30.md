## 今天完成的主要功能

### 蓝牙旋钮

ANTICATER_MINI 实机配对并收到旋转、按压事件。管理页支持扫描、选择、配对、断开和忘记绑定。ESP32-C6 支持 BLE；不支持经典蓝牙。

旋转浏览选项，按压查看或确认；按住逆时针返回，按住顺时针换一组。查看卡片不执行任务，执行需要明确选择。针对多个 HID Report、CCCD 和 Arduino BLE 包装层问题使用了有界原生 GATT 发现与实际 handle 路由，避免扫描缓存挤占 TLS 内存。详见 BLUETOOTH_KNOB.md。

### 声音和录音上传

增加确认、录音开始/结束/取消、错误、连接和任务完成等短提示音；旋转保持安静。管理页可开关、调整音量和试听。用户确认听到了提示音。录音期间禁止提示音，开始音后丢弃短暂麦克风缓冲。详见 SOUND_FEEDBACK.md。

0.11.1 减小录音与编码缓冲，小 WebSocket 帧使用栈缓冲，释放约 14 KB 静态内存，修复 BLE/TLS 共存时录音上传失败的主要内存压力。三次取消型合成上传均完成，无重试且蓝牙、云端保持在线；取消上传没有触发真实 ASR。真实麦克风端到端识别仍应按实际结果验收。

### Linux 语音识别

云端在非 Windows 平台强制使用 whisper 路径，避免旧配置中的 windows 后端触发 `creationflags is only supported on Windows`。修复已部署；不需要再刷 ESP32。

### 围绕目标持续推荐

核心文件是 bridge/goal_flow.py，回归测试 bridge/test_goal_flow.py，详见 RECOMMENDATIONS.md、HARNESS.md 和 TESTING.md。

- 首个实质任务或用户执行的话题卡建立目标；普通临时补充不覆盖原目标。
- 支持语音“新目标是……”和“验收标准是……”。
- 目标、标准、最近动作和结果持久化到 runtime/goal-progress.json，保留最近 30 条结果和 10 个归档。
- 完成、失败或中断后立即提供同一目标下的 A/B 后续；失败偏向修复/诊断，正常完成偏向验证/推进，跳过可调整方向。
- 这是基于阶段与结果的规则版，不是独立生成式规划器。模型说完成只记录为模型报告；没有证据就不标记验证通过。
- 查看、返回、跳过不执行任务。执行仍受运行中、语音、草稿和审批状态保护。
- 收尾必须经“回顾原目标 → 目标已达成，准备收尾 → 确认收尾”。用户接受与实际验证分别记录。
- 长内容分页，先显示行动、理由和预期，完整目标可进档案查看；不自动滚屏。
- 此次推荐改动只需部署云端，无需刷新固件。

## 既有设备配置约定

USB 数据连接主机时优先 USB 配置模式；只充电不能算主机连接。USB 管理通过云端 setup 页面及浏览器 Web Serial；屏幕应显示实际公网地址。AP 模式显示自身地址及端口，通常为 http://192.168.4.1:80/。

Wi-Fi 最多记住 8 个网络，自动选择可用已保存网络；稳定连接时不频繁漫游。配置接口不回传密码。刷固件前在管理页点“断开连接”释放串口，保持数据线连接；不要强制结束整个浏览器。原电脑设备串口曾为 COM10，新电脑须重新确认。

## 运维和后续验收

服务器仓库目录中可运行：

```bash
git pull --ff-only
bash deploy/docker.sh status
sudo python3 deploy/autodeploy.py status
systemctl is-active codex-pocket-autodeploy.timer
sudo journalctl -u codex-pocket-autodeploy.service -n 80 --no-pager
```

自动部署状态在 /var/lib/codex-pocket-autodeploy/state.json。以前发生过回滚失败锁定；先查服务与容器日志、恢复健康，再处理状态。不要直接删锁绕过故障，不要删除数据卷。设备认证、绑定、会话和运行状态需要保留。

下一轮重点：实机走完“设定目标 → 两轮 A/B 推进 → 验证 → 补充验收标准 → 回顾收尾”，观察推荐是否重复、是否真的推动原目标；再做真实录音识别与蓝牙并存的端到端验收。不要把合成上传测试等同于语音全链路通过。
