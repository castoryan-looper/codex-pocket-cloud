# 纵向任务流（Taiji 0.14.0）

一屏一条推荐、任务进度或待决问题。上滑下一条，下滑上一条；旋钮可等价前后浏览。单击与停留不执行任务，双击当前卡片才提交。显示、触摸和确认共享卡片标识，换卡或任务状态变化后，旧确认失效。原 C6 及未协商 taskStream=1 的设备继续使用原 A/B 页面。

## 推荐与偏好

初始候选来自现有目标档案、近 7 天近期聊天/授权导入的聊天、最近任务的实际生命周期结果。每个近期话题提供推进、验证、理解和实验角度；结果后续提供验收或补齐尚存缺口。一次保留最多 24 条候选，尝试避免连续推荐同一话题，已明确选择的卡片被排除。用户确认收尾的旧目标不继续生成执行建议。

排序组合近期性、目标关联、策略/话题偏好，以及少量确定性探索。停留信号来自实际显示回执和每 2 秒可见心跳；断线、配置页面、录音或后台间隔不按整段墙钟时间计入。单次停留上限 30 秒。>=8 秒为弱正反馈（+0.25），<1 秒为弱负反馈（-0.15），明确选择为 +3；一轮 completed 为 +1、failed 为 -0.5。权重更新带 0.98 衰减并限制在 [-8,8]，执行/结果信号高于单纯停留。模型一轮完成不等于目标已达标。

这是一套本地有界排序与反馈算法，不是已训练的大规模推荐模型。个人偏好、有限事件记录和任务参数仅存于服务器私有 runtime，不提交 GitHub。

## 并行与持久状态

最多 2 个独立分析任务运行，每个使用独立 Codex 会话和临时工作目录；只读分析可引用原项目。修改型任务在原工作目录执行并独占调度，等待其他分析完成。权限请求待决时暂停新任务启动；若分析任务需要批准操作，也要等其他任务结束后再显式批准。

最多 12 个未结束/暂停任务，保留最多 40 条任务记录；回收只删除终态历史，不丢弃运行任务。排队卡可双击取消；运行任务旁有单独的停止卡，双击请求停止。一轮结束保留摘要和完整回复，继续推荐围绕原目标的验收或缺口。

队列先落盘再提交；不确定送达不自动重试。重启后未提交的排队任务暂停，提交中/运行中的任务显示状态待核对，不自动重放。未知状态可在对应卡片双击进行只读 thread/read 核对。

## 决策与语音

审批展示人能读懂的请求详情与明确选择。滑动只是阅读；批准前需浏览全部详情页，双击指定选择才发送。请求较长时设备保留拒绝，完整请求在受保护的管理控制台处理。

选择题分别显示各个选项，多题分别选择后才提交整份答案。开放题有独立的问题卡：按住说话回答，录音开始时绑定原问题；识别后先展示答案，再双击提交。原问题已结束时，回答不会作为新任务发送。

管理控制台的“任务流与并行任务”显示每个任务的完整结果、待决请求和答案输入；接口沿用 loopback + bearer token + Origin 检查。公共 USB 配置页仍只负责设备配置。

任务的生命周期、结果和所选步骤写回对应原目标；通过验收任务后会出现“由你确认目标收尾”，只有用户双击收尾才归档。后续确认期间仍有相关未结束任务时不提供收尾操作。
